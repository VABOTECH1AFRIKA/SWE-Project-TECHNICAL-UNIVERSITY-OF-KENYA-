## Before changing anything

1. Inventory the existing skill directories.
2. Read the existing `SKILL.md` files.
3. Identify responsibility overlaps and conflicts.
4. Preserve existing skills unless a safe, justified improvement is required.
5. Verify the installed VS Code Agent Skills format before generating files.

## Implementation rules

- Use one directory per skill.
- Every skill directory must contain `SKILL.md`.
- The `name` frontmatter value must exactly match the directory name.
- Use lowercase kebab-case skill names.
- Keep each skill narrowly specialized.
- Do not create duplicate cross-cutting skills already covered by the existing library.
- Do not invent framework APIs, configuration fields, commands, or behaviors.
- Detect actual project/framework versions before applying version-sensitive guidance.
- Require evidence before making repository-specific claims.
- Never expose, print, commit, or hard-code secrets.
- Do not weaken authentication, authorization, RLS, or other security controls.
- Do not perform destructive database actions without explicit safeguards.
- Use related skills rather than copying their entire instructions.
- Include practical validation steps in every skill.

## Required skill structure

Each `SKILL.md` should contain:

- YAML frontmatter
- Purpose
- When to use
- When not to use
- Required workflow
- Skill-specific rules
- Common failure modes
- Validation checklist
- Related skills
